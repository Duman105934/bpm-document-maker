# BPM Document Maker

Документирование сквозного флоу «мобильное приложение ↔ backend». В одном проекте два связанных слоя:

- **Прототип** — картинки экранов МП, кликабельные зоны, переходы между экранами и вызовы backend через API Gateway
  (как Prototype в Figma).
- **Backend (BPMN)** — редактор схемы из State Machine Modeler с теми же видами элементов:
  Event, State, Cmd, API, Mobile, JSON, DB table.

Gateway-зона экрана открывает схему на нужном узле; узел Cmd/Mobile возвращает на свой экран.
Результат выгружается в PDF-документацию и в один общий SVG.

Веб-приложение без сервера: всё хранится в файле проекта и в браузере.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5174
npm test         # unit-тесты (vitest)
npm run build    # проверка типов и сборка в dist/ (статический сайт)
```

Node 22. Порт 5174 выбран, чтобы не конфликтовать с modeler (5173).

## Как работать

1. **«Файл → Новый проект»** — название, код процесса, описание, автор, версия, дата, картинка-обложка
   (идут на обложку PDF). Остальное в меню «Файл»: открыть, сохранить, настройки проекта, импорт схемы.
2. **Слой «Прототип»:** кнопка «Экраны» или перетащить картинки (PNG, JPG, WebP, SVG) на холст.
   Первый экран становится стартовым.
3. **Зоны — от элементов экрана, как в Figma.** Программа сама находит на картинке кнопки, поля, карточки,
   строки текста и иконки (анализ изображения, без Figma API):
   - наведите на элемент — он подсветится, справа появится «+»; потяните «+» на другой экран —
     появятся зона по границам элемента и переход;
   - «Зона» (клавиша `R`): клик по элементу делает из него зону, прямоугольник мышью — зону вручную
     (для того, что не нашлось автоматически).
   Зону можно двигать, менять размер, удалять клавишей Delete. Координаты хранятся в долях картинки
   и не зависят от масштаба.
4. **Действие зоны** (инспектор справа):
   - «Переход на экран» — или потянуть точку справа от зоны на другой экран;
   - «Вызов через gateway» — метод, внешний URL, сервис и внутренний URL, JSON запроса и ответа, описание и узел BPMN
     (из списка или кнопкой «Выбрать на схеме»).
   У экрана есть ещё «Вызовы при открытии» — запросы без нажатия.
5. **Слой «Backend»:** схема рисуется как в modeler, «Файл → Импорт схемы .bpmn» подставляет готовую.
   У Cmd и Mobile в панели свойств есть поле «Экран прототипа»: на фигуре появляется значок, клик по нему
   открывает экран.
6. **«Проблемы»** — битые ссылки: нет стартового экрана, зона без действия, переход или вызов в никуда,
   Cmd без экрана. Клик по проблеме открывает нужный экран, зону или узел.
7. **«Просмотр»** — единый проход по всему флоу, только для чтения. Проход начинается сам со стартового
   экрана; панель внизу одна на оба слоя, слой переключается сам:
   - «Шаг →» (клавиша →) делает следующий шаг: с экрана — нажатие зоны или вызов при открытии
     (открывается схема, на узел вызова встаёт **токен**, показывается карточка вызова), по схеме —
     по стрелке к следующему узлу, с узла Cmd / Mobile — показ его экрана;
   - «Авто» идёт само: экран → схема → экран. Если шагов несколько (развилка, несколько зон экрана),
     ждёт выбора — кнопкой на панели, кликом по зоне или по узлу — и продолжает. Останавливается
     в конце пути и на уже пройденном месте (защита от цикла);
   - «←» отменяет шаг (клавиша ←), «⟲» начинает сначала. В списке «Экран» и по ссылкам можно перейти
     на любой экран или узел — проход продолжится оттуда.
   Это чтение документации, а не исполнение BPMN: токен всегда один, на параллельной развилке ветку
   тоже выбирает человек.

Отмена: в прототипе Ctrl/⌘+Z и Ctrl/⌘+Shift+Z (свой стек), в схеме — стек bpmn-js, когда фокус на схеме.
Смена вида узла и правка его ID не рвут ссылки прототипа на этот узел.

## Экспорт

| Пункт | Что получается |
|---|---|
| **PDF: документация флоу** | A4 альбомная: обложка, оглавление со ссылками и закладками, затем страницы в порядке флоу. Страница экрана — картинка с номерами зон и выносками (метод и URL, роутинг gateway, JSON, ссылка на узел). Страница узла — фрагмент схемы с подсвеченным узлом и выносками (вид, код, controller / method / endpoint, параметры, JSON, колонки таблиц, ссылки, исходящие потоки развилки). Длинный JSON переносится на страницы-продолжения. Текст выделяется и ищется (PT Sans, PT Mono). |
| **SVG: весь флоу** | Один файл: сверху экраны в порядке флоу со стрелками переходов, снизу схема, между ними пронумерованные пунктирные связи «зона → узел» и «Cmd → экран». Открывается в браузере и в Figma. |
| **BPMN-схема, PDF / SVG / PNG: только схема** | Как в modeler. |

**Порядок флоу** — обход в глубину от стартового экрана: экран → его вызовы (сначала при открытии, затем зоны
сверху вниз) → узлы схемы по стрелкам → Cmd/Mobile с экраном → этот экран → экраны по переходам.
Каждый экран и узел попадает в документ один раз; то, до чего обход не дошёл, идёт в конец с пометкой «вне флоу».
Страницу в PDF получают узлы с видом (кроме JSON и DB — они выноски своей задачи) и развилки.

Экраны при экспорте уменьшаются до 1400 px по высоте, SVG-экраны растеризуются.
Экспортируется корневая плоскость схемы; содержимое свёрнутых подпроцессов во фрагменты не попадает.

## Файл проекта `.fmg`

ZIP-архив:

```
project.json         экраны, зоны, переходы, вызовы, настройки проекта (formatVersion)
process.bpmn         BPMN-схема — обычный .bpmn, открывается и в modeler
screens/<id>.<ext>   картинки экранов как есть
cover.<ext>          картинка-обложка (необязательно)
```

- Связь «зона / вызов → узел» хранится в `project.json` (`bpmnElementId`).
- Связь «Cmd / Mobile → экран» хранится в схеме атрибутом `sm:screen` (id экрана). Namespace расширения —
  `http://bpm-document-maker/schema/bpmn/sm`; у `.bpmn` с прежним URI он заменяется при открытии.
- Открыть / Сохранить / Сохранить как; Ctrl/⌘+O, Ctrl/⌘+S, Ctrl/⌘+Shift+S. В Chrome и Edge файл сохраняется на месте,
  в Safari и Firefox — скачивается. Файл `.fmg` можно перетащить в окно, `.bpmn` — заменит схему после подтверждения.
- Черновик автоматически сохраняется в IndexedDB и восстанавливается после перезагрузки вкладки.

## Структура

```
src/
  App.tsx, app/        шапка, меню, сообщения, иконки, диалоги, панель «Проблемы», действия (открыть, сохранить, экспорт)
  model/               типы проекта, validate/migrate, ссылки и проблемы (refs), геометрия зон, порядок флоу (flow)
  store/               zustand: проект (+ undo через zundo), интерфейс; картинки (assets) — вне store
  io/                  .fmg (fflate), файлы, черновик (idb-keyval), чтение картинок
  prototype/           холст прототипа (@xyflow/react), экран, зоны, инспектор, форма вызова, плеер просмотра,
                       поиск элементов на картинке экрана (detect — анализ, elements — загрузка и кэш)
  bpmn/                создание модельера, редактор и viewer, bpmnBridge (фокус, выбор узла, ремап id), граф схемы,
                       единый проход по экранам и схеме (walk — логика, tokenWalk — токен и слои, WalkBar — панель)
  styles/              app.css — цвета, размеры, кнопки, шапка; layout, prototype, view — по разделам
  modeler/sm/          виды элементов (копия modeler) + SmProjectBridge, значок экрана, element-doc
  properties/          панель свойств (копия modeler) + выбор экрана
  export/              SVG / PNG / PDF схемы, общий SVG (overview-svg), фрагмент схемы (bpmn-fragment)
  export/pdf/          PDF документации: plan → content → layout → render, шрифты, текст
  resources/           пустая схема и пример (example.bpmn)
test/                  vitest
```

### Как добавить поле вида

1. Добавьте атрибут в `src/modeler/sm/moddle/sm.json` (тип `FlowElementExt`).
2. Добавьте поле в `fields` нужного вида в `src/modeler/sm/kinds.js` (с `options` — выпадающий список,
   с `source: 'screens'` — выбор экрана прототипа). Панель свойств подхватит его автоматически.
3. Чтобы поле показывалось в подсказке, в инфо-панели просмотра и в выносках PDF, добавьте его в `FIELD_LABELS` там же.

## Шрифты

PT Sans и PT Mono (ParaType, SIL Open Font License 1.1) лежат в `src/assets/fonts/` и встраиваются в PDF;
текст лицензии — `src/assets/fonts/OFL.txt`.
Казахские буквы поддерживаются. Символы, которых нет в PT Sans (например, «→»), в обычном тексте PDF заменяются
на ASCII-аналоги; в JSON (PT Mono) остаются.
